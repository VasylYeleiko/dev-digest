# dev-digest

Local-first AI pull-request review tool. Course starter — architecture
diagrams and the full lesson roadmap live in [README.md](README.md); this
file is only a map, not documentation.

## Stack

Node ≥22 · pnpm ≥10 · Docker (Postgres/pgvector only — API and web run on the
host, not in containers).

## Commands

- `./scripts/dev.sh` — starts Postgres, migrates + seeds, launches API
  (`:3001`) and web (`:3000`)
- `docker compose up -d` / `docker compose down` — **never** `down -v`
  against a real dev DB, see [e2e/CLAUDE.md](e2e/CLAUDE.md)
- Per-package scripts: see each package's own `CLAUDE.md`

inside that package — you don't need to open them from here.

## Session protocol

- **Start** — once the request identifies a package, read that package's
  `INSIGHTS.md` **before touching code**. Treat its entries as high-confidence
  guidance unless told otherwise. Then confirm you've read it and summarize the
  top 3 points relevant to this task.
- **End** — run `/engineering-insights` before wrapping up. Do not skip this
  step. Append only a genuinely new, non-obvious finding; if the session
  produced none, write nothing and say so.

## Non-default conventions

- **No monorepo workspace.** Every package has its own `package.json` and
  lockfile; shared code (`@devdigest/shared`) is consumed via tsconfig path
  aliases, not a published/linked workspace package.
- `reviewer-core` ships no build output — the server imports its TypeScript
  source directly through a path alias.

## Gotchas

- The server does **not** migrate on boot — run `cd server && pnpm db:migrate`
  after every pull that touches the schema.
- Secrets (`OPENAI_API_KEY`, `GITHUB_TOKEN`, …) live in
  `~/.devdigest/secrets.json` (mode `0600`) or are set via the Settings UI —
  `.env` is only a dev fallback, never the source of truth in that flow.

## Do not touch

- `server/src/db/migrations/*` — generated by `drizzle-kit`, never hand-edited.
- `**/src/vendor/**` — vendored copies (`shared`, `ui`), not package sources.

Full strategy: [TESTING.md](TESTING.md). One test suite per package, each
