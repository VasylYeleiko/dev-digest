# dev-digest

Local-first AI pull-request review tool. Course starter — architecture
diagrams and the full lesson roadmap live in [README.md](README.md); this
file is only a map, not documentation.

## Stack

Node ≥22 · pnpm ≥10 · Docker (Postgres/pgvector only — API and web run on the
host, not in containers).

## Commands

- `./scripts/dev.sh` — starts Postgres, migrates + seeds, launches API
  (`:3001`) and web (`:3000`)
- `docker compose up -d` / `docker compose down` — **never** `down -v`
  against a real dev DB, see [e2e/AGENTS.md](e2e/AGENTS.md)
- Per-package scripts: see each package's own `AGENTS.md`

### Checks

Every package has its own `pnpm typecheck` and `pnpm test` (see its `AGENTS.md`
for the exact invocation — `server` and `reviewer-core` split hermetic vs
integration/build). **There is no lint script anywhere in this repo** — don't
invent `pnpm lint` or assume one runs in CI; typecheck + test is the full check
lane until a linter is added.

Each package's `AGENTS.md` loads automatically once a session touches a file
inside that package (Claude Code picks it up through the package's `CLAUDE.md`
stub) — you don't need to open them from here.

## Session protocol

- **Start** — once the request identifies a package, read that package's
  `INSIGHTS.md` **before touching code**. Treat its entries as high-confidence
  guidance unless told otherwise. Then confirm you've read it and summarize the
  top 3 points relevant to this task.
- **End** — run `/engineering-insights` before wrapping up. Do not skip this
  step. Append only a genuinely new, non-obvious finding; if the session
  produced none, write nothing and say so.
- **Before opening a PR** — run `/pr-self-review`. Any CRITICAL finding means
  the PR must not be opened or merged; `.claude/hooks/pr-gate.mjs` denies
  `gh pr create`/`gh pr merge`/`git push` until a full run passes for the
  exact current changes. Never set `PR_SELF_REVIEW_BYPASS` — that escape hatch
  is the user's alone.

## Non-default conventions

- **No monorepo workspace.** Every package has its own `package.json` and
  lockfile; shared code (`@devdigest/shared`) is consumed via tsconfig path
  aliases, not a published/linked workspace package.
- `reviewer-core` ships no build output — the server imports its TypeScript
  source directly through a path alias.
- **`AGENTS.md` is the source of truth** for agent instructions, at the root
  and in every package. The sibling `CLAUDE.md` is only a one-line
  `@AGENTS.md` import so Claude Code loads it — never put content there.

## Naming conventions

Cross-cutting; each package's own `AGENTS.md` adds conventions specific to
that package.

- **Contracts are the naming boundary.** Wire/DB-facing fields are
  `snake_case` (Zod contracts in `**/src/vendor/shared/contracts/*`, e.g.
  `cost_usd`, `findings_preview`); everything on the TypeScript/Drizzle side of
  that boundary is `camelCase` (`costUsd`, `findingsPreview`). A file that
  reads a DB row and returns it straight over the wire does the
  snake↔camel conversion explicitly, field by field — see
  `server/src/modules/reviews/helpers.ts`'s `findingRowToDto`.
- **Packages, not workspaces.** Directory names are `kebab-case`
  (`reviewer-core`, not `reviewerCore`); each has its own `package.json` name
  under the `@devdigest/*` scope (`@devdigest/web`, `@devdigest/api`, …).
- **Test placement is per package**, never a `__tests__/` tree: `client/`
  colocates `<Subject>.test.ts(x)` next to the component or module;
  `server/` and `reviewer-core/` keep theirs in a sibling `test/` folder.
  An integration test that needs a real Postgres is named `*.it.test.ts` so
  the path filter can split it from the hermetic suite. Tests are
  type-checked: `typecheck` uses each package's `tsconfig.test.json`.

## Gotchas

- The server does **not** migrate on boot — run `cd server && pnpm db:migrate`
  after every pull that touches the schema.
- Secrets (`OPENAI_API_KEY`, `GITHUB_TOKEN`, …) live in
  `~/.devdigest/secrets.json` (mode `0600`) or are set via the Settings UI —
  `.env` is only a dev fallback, never the source of truth in that flow.

## Do not touch

- `server/src/db/migrations/*` — generated by `drizzle-kit`, never hand-edited.
- `client/src/vendor/ui` — vendored copy of `@devdigest/ui`, not a package source.
  (`src/vendor/shared` is different: `server/src/vendor/shared` is the source of
  `@devdigest/shared`, edited in place and mirrored into the client — see
  [server/AGENTS.md](server/AGENTS.md).)
- **Lock files** — `client/pnpm-lock.yaml`, `server/pnpm-lock.yaml`,
  `reviewer-core/package-lock.json`, `e2e/package-lock.json`. Regenerate via
  the package manager after an intentional dependency change
  (`pnpm install` / `npm install`); never hand-edit one to "fix" a conflict.
